# ADR-007 — 캘린더 개편: 일·주·월 보기, 아이폰식 입력, 보호자 캘린더 연동, UI 정리·통일

- **Amends**: ADR-001(의존성 `expo-calendar` 추가), ADR-002(알림 정책: 종료 전 알림 추가), ADR-003(NOW 라인 색, 픽업 캐러셀 노출), ADR-006a(준비물 반복 표시: ↻ pill → 글자 라벨)

## 배경 (사용자 피드백)

1. 귀엽고 아기자기하지만 보기 불편하고 쓰기 애매하다.
2. 캘린더인데 보기가 2~3개로 흩어져 있다(일간 / 자녀 1명 주간 `child/[id]` / 전체 주간 `multi`). 진입 경로도 제각각.
3. 월간·주간·일간을 모두 지원해야 한다.
4. 아이폰(·구글) 캘린더의 구성과 사용감을 닮아야 한다.
5. 보호자 일정도 함께 봐야 한다.

## Decision

### 1. 캘린더 = 한 화면, 세 가지 보기
- 보기: **일 / 주 / 월**. 상단 바의 아이콘 3개 세그먼트로 전환(구글 캘린더의 Day·Week·Month 아이콘 모양). 글자 `WEEK/DAY` 토글 폐기.
- **앱 첫 화면 = 홈(§6-1).** 캘린더 탭을 열면 기본 보기 = 오늘의 일간.
- 상단 바: 왼쪽 큰 제목(일간 `오늘` + 날짜 캡션, 주·월간 `11월` + 연도/주 캡션, 눌러서 날짜 선택) / 오른쪽 `보기 세그먼트 · 검색`.
- **`+`(새 일정)는 하단 독 오른쪽의 둥근 버튼**(2026-11-10 개정 — 상단이 너무 꽉 차서). 캘린더 탭에서는 보고 있는 날짜, 그 외 탭에서는 오늘로 새 일정을 연다.
- **`오늘` 버튼 없음.** 오늘 복귀는 일간 날짜 줄·제목 날짜 선택으로.
- 기존 `app/multi.tsx`, `app/child/[id].tsx` 는 주간 보기 + 자녀 선택(아래 2)으로 흡수되어 **폐기**.

### 2. 자녀 필터 줄 (세 보기 공통)
- 상단 바 바로 아래, 4칸(자녀 최대 3~4 + **보호자**) 알약 버튼. 높이 32, 아바타 22, 가운데 정렬.
- 테두리 1.5px = 자녀 **진한 톤**(아래 5), 바탕 = 자녀 색 25%(보호자 회색 40%).
- **기본 = 모두 활성.** (2026-11-10 개정)
  - **짧게 탭** = 그 사람 켜기/끄기. 꺼진 사람은 버튼 45%, 일정 블록 20%.
  - **길게 누르기** = 그 사람만 켜기(나머지 모두 끔). 혼자 켜진 사람을 다시 길게 누르면 모두 켜짐.
  - 켜진 사람이 한 명뿐이면 그 사람 일정 바탕 **80%**.
  - 데이터는 숨기지 않고 흐리게만(겹침 파악 유지).

### 3. 타임 블록 (아이폰/구글 표기)
- 바탕 = 자녀 색 **60%** 불투명, 왼쪽 **1.5px 세로 막대**(진한 톤), 흰 1.5px 외곽선, 모서리 5~6px.
- 일간: 제목 / 시계 아이콘 + 시간. 시간 표기 **`3–4PM`, `4–5:30PM`, `9AM–2:30PM`**(정각은 분 생략, 오전·오후 같으면 뒤에만). 시간 눈금 `9 AM`, `1 PM`. **AM/PM 유지**(오전/오후로 바꾸지 않음).
- 주간: 칸이 좁아 막대 + 제목만.
- **겹침 = 계단식 포개기**(구글 방식): 같은 날(주간)·같은 열(일간)에서 시간이 겹치면 뒤 일정이 오른쪽으로 밀려 앞 일정 위에 포개진다. 레벨 = 겹치는 앞 일정들이 쓰지 않는 가장 왼쪽 단.
- **고정 일정(학교·어린이집)도 일반 블록과 동일 표시**(얇은 띠 폐기).
- 픽업 필요 = 제목 옆 주황 점(기존 유지).

### 4. 보기별
- **월간**: 날짜 칸 안에 일정 띠(제목, 60% 바탕, **세로 막대 없음**, 시작 시간순). 학교·어린이집 같은 고정 일정은 월간에서 숨김. 칸에 다 안 들어가면 마지막 자리를 **`+N`**(남은 개수)으로.
  - **두 손가락 확대(핀치)**: 일정 띠가 **두 줄**로 — 1줄 제목(넘치면 `…`), 2줄 **시작 시간만**(`4PM`, `4:30PM`). 칸이 높아지고 월간은 세로 스크롤. 다시 오므리면 기본으로.
- **주간**: 시간 그리드 7열, 세로 구분선, 오늘 열 연한 주황. 현재 시각 표시 = 일간과 동일.
  - **두 손가락 확대(핀치)**: 한 화면에 **4일**(기본 오늘부터), 좌우로 넘겨 나머지 날. 블록에 제목 + 시간(`3–4PM`) 두 줄.
- **일간**: 상단 일~토 날짜 줄(넘기거나 눌러 이동) + 자녀별 열 + **보호자 열**. 세로 구분선.
- **오늘 날짜** = 주황 원 + **흰 글씨, 보통 굵기**. **현재 시각** = 주황 선(2px) + 점 + 주황 알약(흰 글씨). 라임색 NOW 라인 폐기(실시간 갱신 동작은 ADR-003 B 유지).
- **픽업 카드**: 일간에서는 숨김. **홈의 다음 픽업 카드로 이동**(§6-1). 여러 픽업의 스와이프 캐러셀 유지 여부는 구현 시 결정.

### 5. 색
- 자녀 팔레트 6색 **값은 그대로**. 서연 = 라벤더처럼 **아바타 ↔ 색 1:1 매핑을 시안·구현 모두 엄수**(`AVATAR_KEYS`).
- 팔레트에 **진한 톤(deep)** 추가: 세로 막대·필터 테두리·색 점용. 시안 확정값 — 핑크 `#D957D9`, 라벤더 `#8E6BE8`, 시트러스 `#A8AD12`, 보호자 회색 `#8E8A83`. 민트·피치·스카이는 구현 시 같은 규칙(명도 대비 3:1 이상)으로 결정.
- 오렌지 위 흰 글씨 대비 ≈ 2.8:1 (본문 기준 미달) — 오늘 숫자·시각 알약 한정으로 수용, 실기기 확인 후 필요 시 굵기/톤 조정.

### 6. 하단 플로팅 독
- 모양(흰 알약, 그림자) 유지. 구성 = **홈 · 캘린더 · 설정** 3탭, **아이콘만(라벨 없음)**, 접근성 라벨은 유지. 활성 = 주황, 비활성 = 회색.
- 알약 오른쪽에 **둥근 검정 `+`**(새 일정).
- 아이콘: 홈 = 기존 `IconHome`, 캘린더 = 신규, 설정 = 기존 톱니.

### 6-1. 홈 = 오늘 요약 (시안 보드 `0 홈`)
- 시스템 화면 바탕(§7-1) 위 흰 묶음 박스. 위에서부터:
  1. 날짜 캡션 + 큰 제목 "오늘"(새 일정은 독의 `+`).
  2. **다음 픽업 카드**(기존 주황 카드 + 자동차 재사용). 보호자 일정과 겹치면 카드 아래 안내 한 줄(화면 표시만, 푸시 없음).
  3. **지금 · 다음**: 자녀별 한 줄 — 진행 중 일정과 끝나는 시간, 다음 일정, 상태 칩("진행 중"/"N분 후"). `캘린더` → 일간.
  4. **오늘 챙길 것**: 오늘 회차 준비물을 일정별로 묶은 체크 목록(완료 n/m). 완료는 ADR-006 회차별 로그 그대로.
  5. **오늘 할 일**: 오늘 마감 할 일 + `할 일 추가` + `전체 보기`(지난·다가오는 할 일 전체 목록 화면).
- **할 일·준비물 독립 탭은 두지 않는다**(홈으로 흡수). 날짜 기준은 항상 오늘.

### 7. 새 일정 화면 (아이폰 캘린더 방식)
- 네이티브 모달(ADR-004). 상단 `취소 · 새 일정 · 추가`(빨강).
- 연회색 바탕 + 흰 묶음 박스(인셋 그룹 리스트). 묶음: `제목·장소` / `자녀·종류`(값 + `>` → 선택 화면) / `하루 종일·시작·종료·반복`(날짜·시간 = 회색 버튼, 편집 중 빨강, 반복 = 별도 화면 + "매주 화, 목" 요약) / `시작 전 알림·종료 전 알림·픽업 필요` / `준비물`(목록 + "매번/이번만" 라벨 + 빨간 `준비물 추가`) / `메모`.
- 라벨은 **"시작"**(일정의 시작 시점. "시작일" 아님).
- 스위치 = 아이폰식. **픽업 필요 스위치 ON = 주황**.
- **기본 박스 모서리 = 14px** (앱 전역 카드/그룹 박스 기본값으로 채택).

### 7-1. 시스템 화면 바탕
- 새 일정 화면의 연회색 바탕(`#F2F1EF`)을 **앱의 시스템 화면 공통 바탕**으로 채택: 설정, 자녀 관리, 캘린더 연동, 데이터, 약관, 일정 상세, 선택 하위 화면. 그 위에 흰 묶음 박스(모서리 14px). 캘린더 화면 바탕은 흰색 유지. 기존 `surfaceSoft`(`#F7F6F5`)는 이 값으로 통합.

### 8. 새 기능 (데이터 변경)
- **하루 종일 일정**: `schedules.all_day INTEGER NOT NULL DEFAULT 0`. 그리드 표시 방식(상단 종일 줄)은 구현 계획에서 확정.
- **종료 전 알림**: `schedules.notify_end_minutes_before INTEGER NULL`. 기존 `notify_minutes_before` = 시작 전 알림. 둘 다 "없음" 가능.
- 마이그레이션 **v8**, additive only, 원자성 게이트(기존 러너 규칙).
- **ADR-002 개정**: "일정 알림 외 새 푸시 surface 금지"는 유지하되, 같은 일정 알림의 **종료 전 시점**은 허용. iOS 64개 한도 정책(MAX_SCHEDULED 60, 가까운 순)은 시작·종료 알림 합산에 그대로 적용.

### 9. 보호자 일정 = 아이폰 캘린더에서 읽기
- `expo-calendar`(신규 의존성, ADR-001 개정)로 기기 캘린더를 **읽기 전용** 조회. 표시할 캘린더는 설정에서 체크. 기기 밖으로 나가지 않음(온라인 기능 없음 원칙 유지).
- 보호자 일정은 세 보기 모두에 회색(`#E4E2DD` 60%)으로 표시, 일간은 보호자 열.
- 권한 거부 시 보호자 칸 = 안내 + 설정 이동.
- (후속, P2) 자녀 일정을 아이폰 캘린더로 내보내기.

### 10. UI 정리·통일
- 개편으로 대체되는 화면·컴포넌트와 이미 안 쓰는 요소를 **일괄 정리**, 남는 요소는 `src/ui/components` 프리미티브로 **통일**. 목록·순서는 계획서 §UI 정리 인벤토리.
- 원칙: 지우기 전 **git 태그(`ui-v1`)로 현 디자인 보존**, 디자인 원본(`docs/design/`)은 유지. 임의 색·크기·모서리 리터럴 금지(토큰 사용) 규칙을 글자 크기·모서리까지 실제로 적용.

### 보류 (이번 범위 아님)
- 자녀 고정 일정 전용 등록 화면(시안 보드 `4`) — 데이터 모델은 이미 지원(요일 반복 vs 1회성), 화면만 후속.
- 앱 이름 변경(미정).

## Consequences
- 라우트 구조 변경: `multi`, `child/[id]`, `kid-switch` 제거, 탭 3개(홈 / 캘린더 / 설정).
- 그리드 3종(ScheduleGrid / WeeklyGrid / MultiKidGrid) → 공통 시간 그리드 + 보기별 래퍼로 재구성. 겹침 레이아웃은 순수 함수(`src/domain`)로 분리해 단위 테스트.
- 알림 스케줄러: 종료 전 트리거 추가, 하루 종일 일정의 알림 기준 정의 필요.
- 신규 권한(캘린더) → App Store 개인정보 문구·`NSCalendarsFullAccessUsageDescription` 갱신.
- 내보내기(JSON) 스키마 v5: `allDay`, `notifyEndMinutesBefore` 포함.
- CLAUDE.md Locked Decisions 의 그리드(06:00–23:00·30분 슬롯), 픽업 시각화(ADR-003), 준비물 ↻ pill(ADR-006a), 알림 정책(ADR-002) 항목은 이 ADR 승인 시 갱신.

## Open Questions
1. 홈 픽업 카드: 픽업 여러 건일 때 스와이프 캐러셀 유지 / 다음 1건만.
2. 하루 종일 일정의 그리드 표시(상단 종일 줄 높이·월간 표시)와 알림 기준 시각(예: 전날 저녁/당일 아침).
3. 보호자 일정 탭 시 동작: 읽기 전용 상세 / 아이폰 캘린더 앱으로 열기.
4. 딥 톤 나머지 3색(민트·피치·스카이) 값.

## 오너 결정 (2026-11-10, ralplan v2 이후)
- **시간 축 = 0–24시**(아이폰식). 초기 스크롤은 현재 시각 근처. 자녀 일정 입력 하한은 별도.
- **할 일·준비물 화면의 날짜 = 항상 오늘.**
- **종료 전 알림으로 알림 한도(60개)가 빨리 차는 것 수용.** 가까운 순 예약 유지.
- **픽업–보호자 일정 겹침 = 화면 표시만.** 푸시 없음(ADR-002/003 잠금 규칙 유지).
- **홈 탭 채택, 독 = 홈 · 캘린더 · 설정(아이콘만), 앱 첫 화면 = 홈.** 할 일·준비물 독립 탭 없음.
