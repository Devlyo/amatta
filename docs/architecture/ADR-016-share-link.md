# ADR-016 — 캘린더 링크 공유 (보기 전용, 서버 저장 없음)

- **Status**: **Accepted / 구현 완료, 배포 완료 — https://wemoa-share.vercel.app/s** (2026-11-12, v2 재배포) — Architect·Critic 리뷰 반영(아래 *Review*) — 오너 "다른 보호자에게 캘린더 화면을 링크로, 수정 불가·일정 정보·주간 뷰까지" → 방식 **A**(데이터는 링크 안에만), 호스팅 **Vercel**, 기본값 = 4주 · 준비물 포함 · 장소·메모 빼기
- **Source**: 디자인 캔버스(비공개) https://claude.ai/artifact/7378YLCUUr4pMf7SgDfybx — 보드 `SH1`–`SH4`. 계획: `.omc/plans/ralplan-share-link.md`
- **Relates**: ADR-001 "온라인 기능 없음"을 **부분 완화** — 앱은 여전히 서버·계정·동기화가 없다. 새로 생기는 건 *정적* 웹 보기 페이지 하나뿐이며, 일정 데이터는 그 서버에 전송·저장되지 않는다.

## Decision
1. **링크 = `https://<host>/s#<payload>`**. payload는 링크의 `#` 뒤(fragment)에만 있다 → 브라우저가 서버로 보내지 않음. 웹 페이지는 받은 fragment를 브라우저 안에서 풀어서 그린다.
2. **payload (v2, 2026-11-12)** = 고른 아이에게 그 주에 보이는 일정의 **반복 규칙**(요일 마스크·시간·시작/끝 날짜·예외·준비물 회차 규칙) + 아이(이름·아바타 번호) + 메타. 반복 요약·종류 이름·아바타 키는 담지 않고 웹이 만듦(한글이 길이 대부분이라). 웹은 앱과 같은 규칙으로 펼침(테스트로 앱 `expandOccurrences`와 결과 일치 확인). v1(펼친 회차, 1천~4천 자)은 카톡에서 링크가 잘려 폐기. JSON → `lz-string` `compressToEncodedURIComponent`, 링크 = `#<버전>.<압축>`(버전이 압축 밖이라 옛 보기 페이지도 "새 버전" 안내 가능). 16K자 넘는 링크·형식이 맞지 않는 값은 거절.
   - 담는 것: 날짜, 시작·끝(하루 종일), 제목, 종류, 함께하는 사람(보호자 포함 여부), 반복 요약 문구, 픽업 여부·시각, (선택) 그 회차 준비물, (선택) 장소·메모.
   - 담지 않는 것: 아이폰 캘린더의 보호자 일정(기기 데이터), 할 일, 완료 기록, 알림 설정.
3. **앱 화면(SH1)**: 캘린더 상단 공유 버튼 → "캘린더 공유": 자녀(기본 전원) · 공유할 일정(준비물 포함 켬, 장소·메모 포함 끔) · **기간은 항상 오늘부터 1주**(오너 2026-11-12, 선택지 없음) · 빨간 경고 → "링크 공유하기" = iOS 공유 시트(문구+링크 한 메시지).
4. **웹 보기(SH2–SH4)**: WeMoa 모양 주간 보기(4일/7일 너비 전환), 주 넘기기(담긴 기간 안), 아이 필터 알약, 일정 누르면 상세 시트(수정 불가 안내). 상단 "보기 전용 · 11월 12일 기준". 기간이 끝났거나 7일 넘게 지난 링크는 안내 띠. 깨진·새 버전 링크는 안내 화면.
5. **호스팅**: Vercel 정적 배포(`web/share/public/`, 빌드 = `npm run share:build`, esbuild로 `src/share/share-codec.ts`를 그대로 묶음 — 앱과 웹이 같은 코드). **외부 요청 0**(CDN·웹폰트·분석 없음, 시스템 글꼴), 엄격한 CSP·`no-referrer`·`noindex`. Vercel Analytics·Speed Insights 끔. 앱 상수 `SHARE_BASE_URL`.
6. **크기**: 아이 4명·1주 기준 링크 < 600자(테스트). 8천 자를 넘으면 준비물·장소를 빼거나 아이를 나누라고 안내.

## Consequences
- 링크를 가진 사람은 누구나 볼 수 있다(취소 불가). 공유 화면에 안내.
- 개인정보 처리방침(legal 화면)에 "공유 링크" 항목 추가 필요.
- 웹 주소가 바뀌면 이미 보낸 링크는 깨진다 → 도메인을 정하면 고정.

## Review (ralplan, 2026-11-12) — 반영 사항
- 고르지 않은 아이는 함께하는 일정의 멤버 목록에서도 빠짐(색·이름도 고른 아이 기준).
- 개인정보 문구: "외부로 전송되지 않음" → "사용자가 직접 공유하지 않는 한", 공유 링크 절 추가(메신저·브라우저 기록에 남을 수 있음, 취소 불가). 공유 화면에도 같은 안내.
- 웹: 링크의 글자는 모두 `textContent`(HTML로 해석 안 함), 인덱스·종류·아바타 값 범위 검사.
- 날짜: `YYYY-MM-DD` + 날짜 차이(정수), 웹은 `new Date(y, m-1, d)`, 시간은 벽시계 분 그대로.
- 하루 종일은 위 줄, 보호자만(기기 캘린더) 일정은 담지 않음(공유 화면에 안내), 보호자 함께는 "보호자 함께" 표시.
- 남은 일: 카톡·메시지에서 링크 전체가 하나로 눌리는지(`$`,`+` 포함) 기기 확인, App Store 개인정보 항목 확인(수집 없음 유지).

## Amendment — 짧은 링크 + 암호화 보관 (2026-11-12, 오너 "짧은 링크로 가자")
- **이유**: 데이터를 링크에 담으면(v2도 1주 ≈ 600자) 카카오톡이 긴 메시지를 접어 링크가 잘림 → "열 수 없는 링크".
- **방식**: 앱이 v2 JSON을 **AES-256-GCM**(링크마다 새 32바이트 키, `expo-crypto` 난수, `@noble/ciphers`)으로 암호화 → 암호문만 `POST /api/share` → 서버(Vercel 함수 + **비공개 Vercel Blob** `wemoa-share-links`, icn1)가 `s/<id>.txt`에 `ttlDays: 14`로 저장(매일 정리, 읽을 때도 14일 지난 건 거절). Upstash는 Vercel 안에서 무료 요금제가 없어 제외(2026-11-12). 링크 = `https://wemoa-share.vercel.app/s/<10자 id>#<키>` (≈ 75자). 키는 `#` 뒤라 서버로 안 감 → 서버·운영자는 내용을 못 읽음.
- **웹**: `/s/<id>` → `GET /api/share/<id>` → 브라우저 WebCrypto로 복호화 → v2 펼치기. 만료 = "기간이 끝난 링크예요". CSP `connect-src 'self'`만 허용. 예전 `#2.…` 링크도 그대로 열림.
- **남용 방지**: 본문 32KB 상한, base64url 형식만, IP당 분당 20건(함수 인스턴스 단위, 공유 저장소 없이 최선 노력). id는 10자 무작위(편향 없는 base62), 덮어쓰기 금지.
- **ADR-001 추가 완화**: 앱에 처음으로 **업로드**(사용자가 공유 버튼을 누를 때만, 암호화된 상태)가 생김. 개인정보 처리방침 갱신. App Store 개인정보 항목 재확인 필요(종단 간 암호화로 운영자가 접근 불가 — "수집 안 함" 유지 여부 확인).
- **새 빌드 필요**: `expo-crypto`(네이티브). 이전 빌드에서는 "업데이트가 필요해요".
