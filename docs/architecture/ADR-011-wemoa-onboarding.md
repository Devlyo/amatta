# ADR-011 — 앱 이름 WeMoa · 온보딩 개편 (3D 얼굴, 권한은 마지막 단계)

- **Status**: **Accepted / 구현 완료** (2026-11-10) — 오너 "온보딩 화면좀 고치자" → 시안 확인 "좋아. 맘에 든다. 그리고 앱 이름은 WeMoa 로 바꾸자"
- **Amends**: 첫 실행 시 부팅 중 알림 권한 요청(`app/_layout.tsx` boot → `ensurePermission()`)
- **Source**: 디자인 캔버스(비공개) https://claude.ai/artifact/7378YLCUUr4pMf7SgDfybx — 보드 `O1 환영 — 3D 얼굴`, `O2 첫째 등록`, `O3 둘째 등록`, `O4 마무리 — 알림·캘린더`

## Context
- 아이 얼굴(아바타)이 3D 렌더로 바뀌었고(2026-11-10), 환영 화면의 평면 마스코트와 스타일이 어긋났다.
- 첫 실행 때 알림 권한 창이 **아무 설명 없이** 부팅 중에 떴다.
- 얼굴이 곧 그 아이의 일정 색을 정한다는 사실(`colorIndexForAvatarKey`)이 화면 어디에도 없었다.
- 앱 이름을 바꾸기로 했다: 아마따 → **WeMoa**.

## Decision
1. **앱 이름 = WeMoa** (표시 이름·문구·스플래시 글자). `APP_NAME`(`src/domain/constants.ts`).
   **번들 ID `io.devlyo.amatta`·slug·scheme은 유지**: 바꾸면 App Store / EAS에서 다른 앱이 된다.
2. **온보딩 = 환영 → 아이 등록(1–4명) → 마무리**.
   - 환영: 3D 얼굴 6개 묶음(천천히 떠오름), 주황 시작하기, "계정 없이, 이 기기에만 저장돼요".
   - 아이 등록: 점 4개 진행 표시, 회색 바탕 + 흰 박스, 미리보기 얼굴 뒤에 그 아이 색, "고른 색이 이 아이의 일정 색이 돼요", 이미 쓴 얼굴은 흐리게 + 그 아이 이름.
   - 마무리(새 단계): 일정 알림(기본 켬)·보호자 일정 함께 보기(기본 끔). **시작하기를 누를 때만** OS 권한을 묻는다. 아이는 이미 저장된 뒤라 뒤로 가기가 없다.
3. **부팅 중 알림 권한 요청은 아이가 있고 알림이 켜져 있을 때만**. 첫 실행은 마무리 단계가 묻는다. 마무리에서 알림을 끄면 `system_notifications_enabled = 0`이 되어 부팅 때도 묻지 않는다(설정에서 켤 수 있음).

## Consequences
- 네이티브 스플래시 이미지·홈 화면 앱 이름은 **다음 빌드부터** 바뀐다(개발 서버 새로고침으로는 JS 쪽만 바뀜).
- **스플래시 = 흰 바탕(다크 `#1A1917`) + 주황 "WeM[핑크 3D 얼굴]a" 워드마크**(Fredoka Bold, 캔버스 보드 `S3-W`). 같은 이미지(`assets/images/splash-icon.png`, `WORDMARK`)를 네이티브 스플래시·JS 부팅 화면·환영 화면 위쪽에 쓴다. 앱 아이콘(주황 얼굴)은 그대로.
- 평면 마스코트(`MASCOTS`)는 더 이상 온보딩에서 쓰지 않는다(파일은 남겨 둠).
