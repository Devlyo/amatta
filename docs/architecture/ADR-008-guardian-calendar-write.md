# ADR-008 — 보호자 일정: 아이폰 캘린더 읽기 + 앱에서 추가(쓰기)

- **Status**: Accepted (2026-11-10, 오너 "A로 하자")
- **Amends**: ADR-007 §9 (보호자 일정 = 읽기 전용) · ADR-001 (의존성 `expo-calendar`)
- **Context**: ADR-007은 보호자 일정을 아이폰 캘린더에서 *읽기만* 하기로 했다. 오너가 "보호자 일정은 어떻게 추가하나"를 묻고 **A안**(앱의 새 일정 화면에서 보호자를 고르면 아이폰 캘린더에 저장)을 골랐다.

## Decision
1. **원천 = 기기 캘린더.** 보호자 일정은 SQLite에 저장하지 않는다. 앱은 `expo-calendar`로 기기 캘린더를 읽고(표시할 캘린더는 설정에서 고름), 앱에서 만든 보호자 일정은 **기기 캘린더에 직접 쓴다**(`createEventAsync`). 기기 밖으로 나가지 않음 — 온라인 기능 없음 원칙 유지(iCloud 동기화는 사용자의 캘린더 설정에 따름).
2. **추가 경로**
   - 새 일정 화면의 "자녀" 줄에 **보호자**가 함께 나온다. 보호자를 고르면 종류·반복·종료 전 알림·픽업·준비물 줄은 숨기고 제목·장소·하루 종일·시작/종료·시작 전 알림·메모만 받는다.
   - 일간 **보호자 열**을 길게 누르면 보호자가 미리 선택된 새 일정.
   - 저장 캘린더 = 설정에서 고른 "새 일정을 저장할 캘린더"(기본 = 기기 기본 캘린더). 쓰기 불가 캘린더는 고를 수 없다.
   - 반복 보호자 일정은 이번 범위 밖(1회성만). 반복이 필요하면 아이폰 캘린더에서.
3. **알림**: 보호자 일정의 "시작 전 알림"은 **캘린더 이벤트의 알람**으로 저장한다(아이폰 캘린더가 울림). 앱의 알림 스케줄러에는 넣지 않는다 → ADR-002 "새 푸시 surface 금지"와 60개 한도에 영향 없음.
4. **보기/수정**: 보호자 일정을 누르면 **iOS 기본 일정 화면**(`openEventInCalendarAsync`, 수정 허용)으로 연다. 닫으면 다시 읽는다. (ADR-007 OQ3 해소)
5. **권한**: iOS 17+ 전체 접근 `NSCalendarsFullAccessUsageDescription` + iOS 15–16용 `NSCalendarsUsageDescription`. 미리 알림 권한은 넣지 않는다(`remindersPermission: false`). Android `READ/WRITE_CALENDAR`. 권한 요청 시점 = 설정에서 연동을 켤 때 또는 보호자 일정을 처음 저장할 때.
6. **설정 저장**: `app_settings`의 `guardian_enabled`, `guardian_calendar_ids`(JSON, 없으면 = 일정 캘린더 전부), `guardian_write_calendar_id`. 기기마다 다른 값이라 **JSON 내보내기에서 제외**, 초기화 시 함께 삭제. 사라진 캘린더 ID는 무시.
7. **사람 6명 레이아웃**: 보호자 2(후속)를 위해 보호자 데이터는 "사람 키" 단위로 다룬다. 지금은 보호자 1(`'guardian'`).

## Consequences
- 새 네이티브 모듈 → **새 개발 빌드 필요**(Expo Go/기존 dev client로는 실행 불가).
- App Store 심사: 캘린더 권한 문구, 개인정보 처리방침에 "기기 캘린더 읽기·쓰기(기기 안에서만)" 추가.
- 테스트: `expo-calendar` jest 목(권한 허용/거부, 캘린더·일정 목록).
