# ADR-013 — 함께하는 일정 (2.0): 일정 하나에 여러 자녀 + 보호자

- **Status**: **Accepted / 구현 완료, 기기 확인 전** (2026-11-11) — ralplan Architect·Critic 리뷰 반영(아래 *Review*) — 오너 "A로 가자"; Q1 = 보기 A(열마다 따로), Q2 = 준비물 함께, Q3 = 보호자도 고를 수 있게, 칸 이름은 "자녀" 그대로
- **Source**: 디자인 캔버스(비공개) https://claude.ai/artifact/7378YLCUUr4pMf7SgDfybx — 보드 `M1`(확정)·`M3`. `M2`(합치기)는 폐기. 계획: `.omc/plans/ralplan-shared-schedules.md`
- **Version**: 앱 2.0.0
- **Supersedes (부분)**: ADR-002 "일정 하나 = 자녀 한 명", ADR-012 "schemaVersion 6↑ 거절"(→ 7↑ 거절), CLAUDE.md Entities 8 tables(→ 9)

## Context
- 일정 하나는 자녀 한 명에게만 속한다(`schedules.child_id NOT NULL`, ADR-002). 가족 모임처럼 여러 아이가 같은 일정을 가지면 아이마다 따로 만들어야 하고, 시간을 바꾸면 모두 하나씩 고쳐야 한다.
- 보호자 일정은 아이폰 캘린더에 저장되고(ADR-008) SQLite에는 없다.

## Decision
1. **데이터**: 마이그레이션 v9 (atomicity-gated, 추가만 함).
   - 새 표 `schedule_children(schedule_id, child_id)`: 두 열 모두 FK에 CASCADE를 걸고, PK는 (schedule_id, child_id)로 한다. 함께하는 **모든** 자녀를 담는다.
   - 기존 일정은 각 일정마다 `(id, child_id)` 행 하나로 채운다.
   - `schedules.child_id`는 남긴다. 값은 **대표 자녀**이고 NOT NULL을 유지한다(열을 빼려면 표를 다시 만들어야 하고, 1.x 데이터와도 맞춰야 해서).
   - 기존 행은 `JOIN children`으로 채워서, 고아 행이 있어도 마이그레이션이 막히지 않게 한다. 트리거(INSERT, `child_id` UPDATE)가 "대표 자녀는 항상 멤버"를 지킨다.
   - 멤버 순서는 대표 자녀가 먼저, 나머지는 id 순이다.
   - `schedules.with_guardian INTEGER NOT NULL DEFAULT 0`: 보호자도 함께하는지.
2. **자녀 삭제**:
   - 그 자녀가 대표인 일정에 다른 자녀가 있으면, 남은 자녀 중 하나를 대표로 바꾼 뒤 지운다(한 트랜잭션).
   - 다른 자녀가 없으면 지금처럼 일정도 함께 지운다.
3. **보기 = A(열마다 따로)**: `expandOccurrences`는 지금처럼 **일정·날짜마다 1개**를 만들고 `memberIds`와 `withGuardian`을 같이 담는다. 사람별 사본은 `fanOutByMember`가 만들고, 일간 열·주간 막대·홈 "지금/다음"에서만 쓴다.
   - 주간 블록 모드(4일 이하)는 한 요일 칸에 모두 그리므로 블록 1개에 겹친 얼굴을 붙인다. 월간은 칩 1개이고, 색은 처음 보이는 사람의 색이다.
   - 일간·주간·월간·필터는 지금 규칙을 그대로 쓴다. 꺼진 사람의 사본은 숨긴다.
   - 보호자 열과 막대에는 `withGuardian` 일정도 그린다(보호자 일정 보기가 켜져 있을 때만).
   - 블록 아래에는 겹친 얼굴을 표시한다(2명 이상일 때).
4. **한 번만 보이는 곳**: 오늘 챙길 것, 검색, 픽업 카드, 알림은 일정마다 하나다. 홈 "지금/다음"은 아이마다 한 줄이므로 함께하는 모든 아이의 줄에 보인다.
   - 이름은 2명이면 "민준·서연", 3명 이상이면 "민준 외 2명"이다.
   - 알림은 회차마다 1개이고, 언제·누구에게 보내는지는 **바꾸지 않는다**(일정의 알림 시점 그대로). 제목의 이름만 바뀐다.
   - 검색은 멤버 누구의 이름으로도 찾는다.
   - 픽업이 자기 자신과 겹친다는 표시는 생기지 않는다(겹침 검사는 아이폰 캘린더의 보호자 일정만 본다).
5. **준비물 = 함께**: 일정에 붙어 있으므로(`checklist_items.schedule_id`) 바꿀 것이 없다. 완료 기록도 회차마다 1개다.
6. **픽업 = 회차마다 1개**: 한 번 데리러 가면 끝이다. `schedule_pickup_log`는 바꾸지 않는다.
7. **새 일정 화면**:
   - "자녀" 칸 이름은 그대로 두고, 펼치면 체크 목록에서 여러 명을 고른다(보드 `M3`). 값에는 겹친 얼굴과 "N명"이 보인다.
   - **보호자만** 고르면 지금처럼 아이폰 캘린더에 저장한다(ADR-008).
   - **자녀 + 보호자**를 고르면 WeMoa에 저장하고 `with_guardian=1`을 쓴다. 아이폰 캘린더에는 쓰지 않는다.
   - 수정할 때도 사람을 바꿀 수 있다. 다만 자녀는 1명 이상이어야 한다(보호자만 남길 수 없음).
   - "이번만" 수정은 사람을 바꾸지 않는다. 이번만 취소·수정, 준비물 완료, 픽업 완료는 **함께하는 모두에게** 적용된다(확인 창 문구에 표시).
   - 자녀 + 보호자는 캘린더 권한을 묻지 않는다. 보호자만 ↔ 자녀와 함께로 바꾸는 것(저장 위치가 바뀜)은 수정 화면에서 할 수 없다.
8. **백업**: 내보내기 `schemaVersion` 6에 `schedules[].memberIds`와 `withGuardian`을 넣는다. 가져오기는 멤버를 검증하고(자녀가 있는지, 대표가 들어 있는지, 중복이 없는지) `schedule_children`도 먼저 지운다(배타 연결은 FK가 꺼져 있어서). 가져오기는 3–6을 받고, 3–5 파일은 `child_id` 하나짜리로 바꾼다. 7 이상은 거절한다.

## Consequences
- 같은 일정이 여러 열에 보인다. 일정 수를 셀 때는 회차 수가 아니라 `(scheduleId, 날짜)` 기준으로 센다.
- 보호자 일정이 두 곳에 있게 된다(아이폰 캘린더 = 보호자만, WeMoa = 자녀와 함께).
- 1.x 앱은 v6 백업 파일을 거절한다(앱을 업데이트하라는 안내가 뜬다).

## Review (ralplan, 2026-11-11) — 반영 사항
- Critic: 홈 "지금/다음"은 중복 제거하면 안 된다. 알림 계획이 없는 동작(아이별 켜기·끄기)을 가정했다. `expandOccurrences`를 쓰는 곳이 5곳이다. 픽업이 자기 자신과 겹친다. 자녀 + 보호자가 캘린더 권한을 탄다. → 일정마다 1개 + 펼치기를 고르는 방식으로 바꾸고, 알림 시점은 바꾸지 않는다.
- Architect: 가져오기에 `schedule_children`가 빠져 있었다. 저장소를 거치지 않는 INSERT(시드·가져오기)에 대비해 트리거를 둔다. 백필은 JOIN으로 한다. 자녀를 지운 뒤 일정 스토어를 다시 읽고 알림을 다시 잡는다. 블록 id가 겹친다(`${scheduleId}` → 사람별 id). 주간 블록·월간은 1개만 그린다.
- 보류: 보호자도 함께하는 픽업 일정이 픽업 카드를 띄울지 → 지금은 그대로 띄운다(오너 확인 필요).
